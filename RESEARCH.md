# Research and source audit

Research baseline: `GOAL.md` was supplied with a source bibliography dated 20 November 2026. Its product-reference and component tables are research leads, not evidence that this repository has integrated or revalidated those sources.

## Required audit before adoption

- Reconfirm exact upstream commit/tag, source files, full license text, transitive dependencies, supported architectures, sample-rate behavior, algorithmic delay, CPU/memory requirements, and parameter semantics.
- Preserve GPLv3-compatible distribution; exclude GPL-2-only, unknown-license code, proprietary binaries, and assets without redistribution rights unless a compatible grant is verified.
- Record upstream links and exact versions in `THIRD_PARTY_NOTICES.md`; record integration changes and build recipe here.
- The Amp Rack audit in `GOAL.md` identifies a pinned source snapshot and warns that bundled binary libraries, commented-out source modules, and individual effect licenses must be considered separately.
- Pitch candidates in `GOAL.md` are not yet integrated, built, or measured in this project. Do not treat library buffer/window values as end-to-end latency.

The first real-audio pass found one malformed EGFxSet WAV whose single zero word-padding byte was counted in the 24-bit data chunk. The WAV reader now accepts and removes exactly one terminal zero byte when it is the only alignment remainder. CLI tests cover this case, reject a non-zero terminal byte, and reject a two-byte remainder. This is a narrowly bounded compatibility rule, not permission to ignore arbitrary malformed audio.

## First local DSP benchmark (2026-11-20)

`make bench` on an AMD Ryzen 9 5950X / GCC 13.3.0 / Release / 48 kHz / 128-frame stereo blocks / 2,000 warm-up and 5,000 timed calls gave callback-deadline p50/p95 of 0.0056/0.0064% for input gain, 0.0184/0.0188% for Noise Gate, 0.1429/0.1448% for Soft Drive, 0.0589/0.0596% for normal Digital Delay, 0.0897/0.1560% for ping-pong Delay, 0.0743/0.0750% for dual mono, 0.0896/0.0908% for dual stereo, 0.1077/0.1084% for four-tap mono, 0.1380/0.1451% for four-tap stereo, 0.0420/0.0439% for Vibrato, and 13.2758/16.8192% for the 25-effect chain with controls and meters. Full per-effect percentiles, memory, and limitations are in `LATENCY_AND_QUALITY.md`. This uses a deterministic synthetic buffer, not the downloaded guitar corpus or the audio backend, so it does not establish live round-trip latency.

## DSP benchmark update (2026-11-21)

The benchmark reports p50/p95/p99/p99.9/max callback-deadline percentage, directly owned processor memory, each processor separately, signal controls, and an aggregate chain. It includes input/output gain, volume pedal, high/low-pass filters, noise gate, pedal/studio compressors, expression and envelope wah, clean boost, transparent, mid-focused, and high-gain distortion, Round Fuzz, soft drive, tremolo, chorus, flanger, phaser, vibrato, parametric EQ, delay, polyphonic pitch shift, peak limiter, and input/global/panic controls. The latest 25-effect measurements plus the signal-control layer, full configuration, and memory definition are recorded in `LATENCY_AND_QUALITY.md`; they remain Linux desktop processor-call results, not live audio-device measurements. Delay uses a shared 2 s ring: 768,584 B stereo for normal, ping-pong, dual, and multi-tap; the mono multi-tap instance uses 384,580 B. Four-tap p50/p95 is 0.1077% / 0.1084% mono and 0.1380% / 0.1451% stereo. Normal, ping-pong, and dual values are in the benchmark table. The full chain measured 13.2758% p50 / 16.8192% p95 and 29.7128% max; host scheduling affects tail values, and this does not establish live audio-route performance. These project-authored processors are generic styles; clean boost reuses the shared Gain stage. No product-specific sound or hardware performance is claimed.

The in-house compressor and EQ add no third-party source or asset dependency. Their exact control ranges, default values, channels, latency limitations, owned memory, and automated evidence are recorded in `EFFECTS_MATRIX.md`.

## Browser/WASM prototype verification (2026-11-21)

`make web-test` compiles the same C++ DSP source to Emscripten WebAssembly and validates the browser Play path in headless Chrome using a locally generated mono guitar-like fixture. The audio graph stays in the page; no user file or test audio is uploaded. The browser captures processed samples in a SharedArrayBuffer and compares them with `tabletfx_offline` output. Results and tolerance are in `AUDIO_COMPATIBILITY.md`.

The test uses CDP over a local WebSocket rather than Chrome's `--dump-dom` virtual-time runner: that runner loaded the worklet module but did not execute render callbacks. The CDP test confirmed the browser worklet callback runs. Chrome 151 exposed `Date.now()` but not `performance.now()` in this AudioWorklet, so per-effect live percentages use 1 ms resolution and are expressly coarse. The HTML reports this limitation, and the native high-resolution measurements remain in `LATENCY_AND_QUALITY.md`.
