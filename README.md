# TabletFX

An offline guitar multi-effects application for Android, Linux, and Windows, with a browser/WASM guitar-audio test page. The C++20 DSP core is shared across native builds and the browser AudioWorklet; native audio backends are Oboe, JACK/PipeWire, and WASAPI.

Project status: the Linux offline core implements smoothed input/output gain, an expression volume pedal, high-pass, low-pass, a hysteresis-and-hold Noise Gate, a four-control pedal compressor, a studio compressor, pedal wah, Soft Drive, tremolo, Delay, a three-band parametric EQ, and an output peak limiter. Automated DSP/CLI tests, per-effect and full-chain CPU/memory benchmarks, and a prerecorded-guitar regression path are available. The browser test page loads a local audio file, exposes expression position/taper/endpoints, gate/wah/tremolo controls, and output protection; shared C++ DSP runs through WebAssembly/AudioWorklet and captured Play output is compared with the native renderer. Manual audible-output/listening verification remains open. Chrome 151's worklet exposes only a 1 ms timer in this environment, so the browser's live per-effect CPU percentages are coarse. An initial Windows WASAPI backend and MinGW cross-build are present, but the backend is not integrated into the app UI or run on Windows hardware. The native application UI, Android/Linux live audio backends, and hardware configurations remain unverified.

Start with [`GOAL.md`](GOAL.md), [`IMPLEMENTATION_CHECKLIST.md`](IMPLEMENTATION_CHECKLIST.md), and [`ARCHITECTURE.md`](ARCHITECTURE.md). Run `make doctor` to inspect locally available toolchains. Run `make audio-fixtures-plan` to review the licensed prerecorded test audio and the selected external volume; `make audio-fixtures-fetch` downloads and verifies it outside the repository, then creates the ignored `testdata/reference_audio` symlink. Set `MULTIFX_AUDIO_DATA` to override automatic volume selection.
