# TabletFX

An offline guitar multi-effects application for Android, Linux, and Windows, with a browser/WASM guitar-audio test page. The C++20 DSP core is shared across native builds and the browser AudioWorklet; native audio backends are Oboe, JACK/PipeWire, and WASAPI.

Project status: the Linux offline core implements smoothed input/output gain, an expression volume pedal, high-pass, low-pass, a hysteresis-and-hold Noise Gate, a four-control pedal compressor, a studio compressor, pedal wah, envelope/touch wah, a transparent clean boost, low-gain transparent-style and mid-focused soft-clipping overdrives, high-gain distortion with pre/post filtering, rounded fuzz, Soft Drive, tremolo, chorus, flanger with signed feedback polarity, a selectable 4/6/8-stage phaser, vibrato, project-authored Room and Hall Reverbs, free-time and tempo-synced Digital Delay with Slapback, warm BBD-style coloration, and project-authored Tape Echo saturation/wow/flutter, stereo ping-pong routing, independent A/B delay lines, a four-tap pattern with per-tap time, level, and pan, and selectable 1×–4× multi-head routing. The processor set also includes optical/FET-style compressors, guitar/bass graphic EQs, and low-shelf/high-shelf/tilt EQ. Automated DSP/CLI tests, per-effect and full-chain CPU/memory benchmarks, and a prerecorded-guitar regression path are available. The browser test page loads a local audio file, exposes a categorized effect picker including Reverb, a ±12-semitone pitch control, expression position/taper/endpoints, per-block bypass, global bypass, input mute, panic mute, input/output peak and RMS meters with clip indicators, Room Reverb size/decay/predelay/damping/mix/level and Hall Reverb decay/predelay/damping/low-cut/mix/level controls, gate/boost/overdrive/high-gain distortion/round-fuzz/expression-wah/touch-wah/tremolo/chorus/flanger/phaser/vibrato/tempo-sync, dual-delay, multi-tap, BBD, Tape Echo, multi-head, optical/FET compressor, guitar/bass graphic EQ, and shelf/tilt EQ controls, and output protection; shared C++ DSP runs through WebAssembly/AudioWorklet, and pressing Play outputs the processed chain for local audio. Run `make web-serve` and open `http://127.0.0.1:8000/web/` to select a local guitar recording, adjust the chain, and press Play; audio stays on this machine. Automated Play capture is compared with the native renderer. Manual audible-output/listening verification remains open. Chrome 151's worklet exposes only a 1 ms timer in this environment, so the browser's live per-effect CPU percentages are coarse. An initial Windows WASAPI backend and MinGW cross-build are present, but the backend is not integrated into the app UI or run on Windows hardware. The native application UI, Android/Linux live audio backends, and hardware configurations remain unverified.

Run `make audio-fixtures-plan` to review the licensed prerecorded test audio and the selected external volume; `make audio-fixtures-fetch` downloads and verifies it outside the repository, then creates the ignored `testdata/reference_audio` symlink. Set `MULTIFX_AUDIO_DATA` to override automatic volume selection.
